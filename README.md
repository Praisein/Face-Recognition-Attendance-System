# Face-Recognition-Attendance-System

A college project — a Flask web app that uses a device camera to recognize students' faces (from local images/encodings) and mark attendance. The app also contains IP/mobile access controls so other devices must be permitted before they can use the attendance page.

This README explains how to prepare data, train/generate face encodings, add a PyTorch model, run the app, and troubleshoot common issues.

---

## Quick summary / Quickstart

1. Put each student's face image inside `static/student_images/` and name the file with the student ID (e.g. `12345.png`).
2. Run the training script to generate `EncodeFile.p`:
   - python3 -m venv venv
   - source venv/bin/activate  (Windows: `venv\Scripts\activate`)
   - pip install required packages (see Requirements)
   - python train_images.py
3. Place your PyTorch model file in a folder named `models/` (for example `models/model.pth`) — the app expects a model in `models/`.
4. Start the Flask app:
   - python app.py
5. Open the app in a browser:
   - Local: http://localhost:5000
   - Network devices: http://<machine-ip>:5000 (other devices need permission through the access control flow)

## Requirements

- Python 3.8+ recommended
- Camera (built-in or USB) for live capture
- A pre-trained PyTorch face model (see "Model" below)
- Python packages (minimal list; install with pip or add a `requirements.txt`):
  - flask
  - opencv-python
  - face_recognition
  - dlib (face_recognition dependency; installation varies by OS)
  - numpy
  - pillow
  - torch
  - torchvision

Note: face_recognition/dlib can be tricky to install on some platforms. If you use conda, installing `dlib` and `face_recognition` from conda-forge is often easier:
- conda install -c conda-forge dlib face_recognition

## File / Directory overview

- app.py — Flask application entrypoint (run this to start the web app)
- train_images.py — script to build face encodings from `static/student_images/` and save `EncodeFile.p`
- static/

- student_data.json, teacher_data.json — simple JSON files used by the app to store metadata

- mobile_routes.py, mobile_camera.py — mobile-related routes and utilities
- attendance_core.py, attendance_system.py — core attendance logic and helpers

## Prepare student/teacher images

- Student images:
  - Put images in `static/student_images/`.
  - Filename must be the student ID (e.g. `1001.png`, `s123.jpg`). The script uses the filename (without extension) as the ID.
  - Use clear front-facing photos. PNG or JPG recommended.
- Teacher images:
  - Put images in `static/teacher_images/`. These are typically used for display/auth and are not included in the encoding file by default.

---

## Generate face encodings

1. Ensure student images are in `static/student_images/`.
2. Activate your virtual environment and install dependencies (see Requirements).
3. Run:
   - python train_images.py

What it does:
- Loads each image from `static/student_images/`.
- Detects and encodes faces using the face_recognition library.
- Saves a file named `EncodeFile.p` (pickle) containing encodings and their corresponding IDs.
- If a file has no detectable face, it will be skipped (check console output).

Important: If a student image produces "No face detected", try a different photo or crop/resize it so the face is visible and large enough.

## Add your PyTorch model

- Create a `models/` folder in the repository root.
- Place your trained PyTorch model file into `models/`. Common names: `model.pth`, `model.pt`.
- The application will expect a model in `models/`; if your model has a custom filename or load routine, update `app.py` or the relevant model-loading code to match the filename/format.

Note: The repository currently expects you to supply a model compatible with how the app loads it. If you are unsure how the model is loaded, check `app.py` and related model-loading code to see the exact path/filename and required format.

## Run the Flask app

1. Activate your virtual environment.
2. Start the app:
   - python app.py
3. Default URL:
   - http://localhost:5000
4. To allow network access (so mobile devices can connect), ensure the host machine firewall allows the port and use the machine IP:
   - http://<machine-ip>:5000
   - Other devices may be blocked until the main user permits them; the repository contains IP/mobile access control code (see `ip_access_config.json`, `mobile_access_control.json`, and `init_ip_config.py`).

If your app binds to 0.0.0.0 or a specific host/port, check `app.py` for the exact run command.

## Common troubleshooting

- face_recognition / dlib install fails:
  - On Linux: install build tools (build-essential), cmake, and system dependencies before pip installing dlib.
  - On Windows: consider using pre-built wheels or the conda-forge channel.
  - Easiest cross-platform approach: use conda and install `dlib` and `face_recognition` from conda-forge.
- Camera not found or access error:
  - Ensure the camera is not used by another application and that the runtime has permission to use it.
  - On some systems, OpenCV device index may differ; debug with a small script that tries different camera indices.
- No face detected in training:
  - Use high-quality, front-facing images.
  - Crop/rescale images so faces occupy a significant portion of the photo.
- EncodeFile.p missing:
  - Run `python train_images.py` again and confirm it created `EncodeFile.p` in the repo root.
- App port conflict:
  - If port 5000 is in use, either stop the other service or modify `app.py` to use a different port.
